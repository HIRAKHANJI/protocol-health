# v8.10.9 — De-personalization + Multi-Perspective Audit Register

Five parallel read-only scans ran against v8.10.8 on 2026-11-01: personal-data
sweep · data layer/boot · math engines (run under node) · daily UX flows
(headless Chromium at 375px, incl. a fresh install) · plan-content correctness.
Every finding below was re-verified against source before acting. **FIXED** =
shipped in v8.10.9. **DEFERRED** = documented, untouched (needs a design decision
or larger rework).

## 1 · De-personalization (FIXED)

The app shipped one person's details as built-in content: CYCLE hardcoded a
currency, two named stores, Sep–Oct 2026 dates, ~101 → 92kg waypoints, a 1,000-cal
sprint and personal history; `app.html`/`radar.js` fell back to 104kg / 91kg;
Settings preselected "Aggressive — your protocol"; AGRO carried one person's
supplement brands and label doses and "extra right side" hip work; the public
landing page changelog named a city, a flight and weigh-in gates, and its demo
"AUTO TDEE 3,536" was exactly that person's Mifflin result.

- `plans/cycle.js` rewritten: every number derived at render time from Settings +
  logs. Modes are computed (GLIDE / BAND / BELOW vs `targetKg` ± 2kg, calories
  from `s.tdee`), protein floor 1.6 g/kg × latest weight, run ramp relative to
  week number, generic shopping list, no dates/currency/stores/history.
- Neutral HTML defaults (`—`) and placeholders; `risk` default `standard`; no
  `|| 104` / `|| 91` fallbacks (goal bar shows "Set a target weight"; radar GOAL
  axis hidden without a target; protein floor says "log your weight").
- AGRO supplements generic and UL-compliant (D3 1–2,000 IU, calcium only if diet
  is low, magnesium 200–300mg, omega-3 1–2g; explicit NIH-limit notes).
- Landing page: changelog rewritten generically, demo data neutral.
- Kept on purpose: the creator credit in `manifest.json` (product authorship, not
  user data) — remove if unwanted.

## 4 · DEFERRED

- END TODAY / REMOVE clear ALL future fast/light days incl. hand-marked ones (needs per-day provenance). Confirm text now says so plainly.
- `isFastBroken` is session-wide; live multi-day session `dates[]` frozen until it ends; surfaces disagree on session-only fast days; deleting the breaking food doesn't un-break; `editSession` re-homes to today; unset maps never cleared; most-recent-session uses storage order.
- Workout row ids are positional (`wex0..N`) — editing a plan's content remaps past workout ticks.
- Past days are judged against the CURRENT plan's checklist (no per-day plan stamp).
- Previewing a plan in Settings can persist activity level / linked offset before CONFIRM.
- Workout engine BETA rows aren't tickable; Settings still offers the toggle on plans without a template.
- Backup reminder and update banner can overlap; calorie card passes with no food logged; DAY_SAVED doesn't refresh an open TODAY water card; day-modal notes unescaped in the textarea; calendar month doesn't roll over while open.
- Older-schema backups restore un-migrated (now without rolling the schema record back); `downloadJson` can't detect a blocked download; `reverse()` migrations unused.
- Projection formula window vs days-to-Sunday; 0.75 observed-blend cap unreachable; inference cap note text; Reality Check hides loss rows on all-fast windows; loss sign display; DST ms math in spike trim; future-dated weights.
- Calculator: MODE B has no maximum-days cap; ADJUST displays "--" when calories > TDEE.
