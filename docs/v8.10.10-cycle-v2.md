# v8.10.10 — CYCLE v2 (owner-approved)

Approved in chat on 2026-11-06 after the 55-day plan discussion ("make the rest of
the updates to the app under the CYCLE plan … so it can last against coming months").
The plan was proposed and discussed first; this file records what was built.

## Design

- **Long-running, data-driven.** Nothing is dated. The mode (GLIDE / BAND / BELOW)
  comes from the latest weight vs `targetKg`; fast days, the Thursday session, protein
  floor and banner copy follow it. The run ramp follows the week number since
  `startDate` and is open-ended after week 12.
- **Eating window 9AM–4PM, two meals** via `defaultTimes`; the user can change the
  window in Settings and every label follows (`getPlanTime`).
- **Fasts:** GLIDE Thu + Sun, BAND Sun, BELOW none. A fast runs from meal 2 the day
  before to meal 1 the day after; never two in a row; no training on a fast.
- **Water:** ~33 ml/kg rounded to 0.5L (2.5–4.0L), fast days +0.5L (≤4.5L), salted.
- **Protein:** 1.6 g/kg of target weight in GLIDE, else of current weight.
- **Supplements:** creatine 5g daily; D3 1,000–2,000 IU + multivitamin (+ optional
  omega-3) with meal 1 on eating days; magnesium glycinate 200–300mg nightly; salt on
  fast days; caffeine ≤400mg before 2PM. All within CLAUDE.md §15 limits.
- **Re-entry:** week 1 no fasts at ~70% volume, week 2 Sunday only, week 3 full plan.
- **Growth path:** the 12-week checkpoint is where harder variations / blocks get
  added; progression tracks (`exRowWithLevel`) already carry level-ups.

## Known limits

- Fast days already written to the calendar don't change when the mode changes —
  REMOVE + re-add the schedule, or tap days in MONTHS (documented in RULES).
- The weekly-numbers card uses a constant TDEE (no adaptation term); weekly
  calibration on TRACK replaces the estimate with observed burn.
- Weeks 1–2 re-entry fasts are not auto-skipped; the RULES card tells the user to
  unmark them in MONTHS.
